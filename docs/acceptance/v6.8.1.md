## Windows 原生证据

系统版本：Windows NT 10.0.26300.0。Electron 42.11.3。本机仅有一台显示器。

通过 Windows 设置 UI 实际切换分辨率及对比度主题。测试不使用 `force-device-scale-factor` 或强制颜色模拟；Playwright 的默认颜色覆盖通过 `emulateMedia({ forcedColors: null, colorScheme: null })` 移除，并要求 Electron 主进程原生高对比度标志与渲染器媒体查询同时成立。原生标志含义见 [Electron nativeTheme 文档](https://www.electronjs.org/docs/latest/api/native-theme)。

| 模式 | 实际逻辑工作区 | 初始窗口边界（x/y/w/h，DIP） | 结果 |
| --- | --- | --- | --- |
| 2560×1600／175%，夜空深色高对比度 | 1463×915 | 92/8/1284/905 | 三个按钮图形与边界可见、能聚焦；最大化、还原、最小化、关闭通过 |
| 2560×1600／175%，沙漠浅色高对比度 | 1463×915 | 92/8/1284/905 | 同上；通过 Computer Use 实际使用 Win+Left 分屏，并拖动标题栏退出分屏 |
| 1920×1080／150%，普通主题 | 1280×720 | 2/2/1278/717 | 创建、还原、最小化、关闭及原生半屏通过；半屏实测约638 DIP宽，导出和复制首屏可达 |
| 1366×768／125%，普通主题 | 1093×615 | 2/2/1091/612 | 同上；半屏实测546×614 DIP，导出和复制首屏可达 |

运行中由1920×1080／150%切到1366×768／125%，既有窗口调整为 `2/2/627/612`，处于新工作区内。原生验收发现并修正了贴边窗口在分数缩放下向外舍入的问题。工作区约束为普通窗口预留边界；最大化和全屏尺寸继续交由系统管理。

本地 JSON 和应用截图位于 `output/playwright/v6.8.1-native/{night-175,desert-175,1920-1080-150,1366-768-125}/`，其中 `acceptance.json`、`interaction-samples.json` 记录实际显示参数和窗口边界。这些是本地忽略的验收产物，不是 CI 或公开发布资产。验收结束后已通过设置 UI 恢复2560×1600／175%及“无”对比度主题。

**剩余原生 Gate：** 在两台不同 DPI 的显示器间往返拖动，检查正常、最大化后还原、拔除显示器后的恢复与各步操作可达性。当前只有单屏，负坐标／移除显示器的单元测试不能替代此验收。

复验入口（在对应 Windows 实际设置下运行）：

```powershell
npm run desktop:hig-test -- --label=night-175 --expected-scale=1.75 --require-high-contrast
npm run desktop:hig-test -- --label=desert-175 --expected-scale=1.75 --require-high-contrast
npm run desktop:hig-test -- --label=1920-1080-150 --expected-scale=1.5
npm run desktop:hig-test -- --label=1366-768-125 --expected-scale=1.25
```

`--interactive` 仅供现场验收：测试最多保留窗口5分钟，记录原生边界变化，创建该次输出目录中的 `continue` 文件后继续关闭检查。复验应使用新的 label，避免复用旧继续文件。
