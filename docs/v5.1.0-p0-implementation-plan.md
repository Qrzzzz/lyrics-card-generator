# v5.1.0 P0 implementation plan

This release is limited to the four stability blockers in issues #55-#58. The
existing v5 import and lyrics-workspace presentation remains unchanged.

## 1. Document revision and import transactions

- Add one editor-owned document transaction controller. Every intent that can
  replace the active song (`search`, `link`, `local audio`, `example`, and
  `clear`) advances the document revision and aborts older work.
- A result may commit only when its token is still the latest token for the
  current document revision. Lyrics candidates carry the song identity and
  revision that produced them, so a candidate cannot be applied after a clear
  or song replacement.
- Replace song documents canonically instead of partial-merging `SongInfo`.
  Missing cover, explicit, final URL, and parse method fields are cleared. A
  song replacement also replaces its original lyrics atomically and clears an
  old translation; direct lyric editing preserves the current original and
  translation until the user changes them.

## 2. Safe fetch

- Introduce one Node-only safe-fetch transport used by the image proxy and all
  untrusted song/parser URL fetches.
- For every hop: parse the URL, resolve all addresses, reject every non-public
  IPv4/IPv6 (including mapped forms and reserved ranges), then connect through
  a resolver pinned to one of those already-validated addresses. Redirects are
  manual; relative `Location` values restart the same validation before the
  next request.
- Enforce one total deadline, a redirect limit, response-body budgets, and
  caller-specific content-type allowlists. AI custom base URLs remain outside
  this public-media policy.

## 3. Immutable ExportSnapshot transaction

- Build a serializable, deep-frozen `ExportSnapshot` containing revision,
  song, lyrics, style, locale, pixel ratio, exact dimensions, and filename.
- Acquire a ref-backed synchronous mutex before any `await`. Mount the export
  host from that snapshot only, wait for React/DOM readiness, validate that
  same snapshot, and capture it. Live edits may continue but cannot alter the
  in-flight export. Failures and busy attempts surface localized feedback.

## 4. Shared Desktop/Web Lite export safety contract

- Move line-count, fonts, measuring, exact-size, auto-height, and real-overflow
  decisions into a shared library contract. Desktop and Web Lite supply the
  same snapshot plus DOM measurements and receive the same blocking reason.
- Web Lite gets its own off-screen export host and uses the same snapshot
  transaction instead of capturing the collapsible visible preview.
- Deterministic tests cover the 36/37-line boundary, fixed-canvas overflow,
  font/measuring blockers, snapshot consistency, and same-turn mutual
  exclusion. Browser tests also prove a collapsed Lite preview does not affect
  export.

## Delivery

- Keep changes in small commits for safe-fetch, import transactions, export
  transactions/contracts, and 5.1.0 release surfaces.
- Run the required verification chain in order, produce installer and portable
  artifacts, record SHA-256, push `codex/v5.1.0-p0-fixes`, and open one PR that
  closes #55, #56, #57, and #58 without merging it.
