# 示例歌曲维护流程

示例歌曲界面的配色直接来自专辑封面。真实封面只在开发期临时下载并参与本地取色，不生成中间歌词卡图片，也不随应用分发。

## 流程

1. 在 `lib/examples.ts` 新增真实的歌曲、歌手、专辑信息，以及原语言歌词和各语言翻译。
2. 运行 `npm run examples:generate-palettes`。
3. 脚本解析歌曲链接，将真实封面临时写入 `tmp/example-covers/`。
4. 开发专用的 `example-palette-generator` 页面直接对封面执行调色板提取。
5. 脚本将每首歌曲的 2 到 6 个颜色同步到 `lib/examples.ts` 的 `palette.colors`。
6. `ExamplesFloor` 将这些颜色作为整张竖版卡片的连续背景，不显示封面、模拟内容或显式色条。
7. 卡片文字复用界面的明暗对比度算法；浅色背景自动使用深色文字，深色背景自动使用浅色文字。
8. 整张卡片是唯一的导入控件；底部“载入示例”只提供视觉导向，不再嵌套第二个按钮。

## 约束

- 不得提交真实专辑封面。
- 不得把真实专辑封面放入 `public/`。
- 不得把真实专辑封面打包进桌面应用。
- `palette.extractedFrom` 必须为 `album-cover`，不能从生成后的歌词卡或截图二次取色。
- `palette.colors` 只保存合法的十六进制颜色，数量为 2 到 6 个。
- 每首示例必须包含可离线显示的真实 `album`；卡片只展示真实文字元数据和载入按钮。
- 点击卡片任意位置、或在键盘聚焦后按 Enter / Space，都必须触发同一个导入动作。
- 示例歌曲界面不在运行时请求远程封面；离线状态继续使用已同步的颜色元数据。
