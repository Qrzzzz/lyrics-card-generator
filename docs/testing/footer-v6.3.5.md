# v6.3.5 页脚与依赖更新本地验收

本文记录发布前的本地开发验收快照。基线为 `7a40f99b182d9475898f3985643c30a85a4f8e34`，开发分支为 `codex/v6.3.5`；正式发行证据以同版本 GitHub Release 工作流为准。

## 实现约定

- 分享人和项目署名继续独立控制。仅渲染可见行；只有同时显示两行时才产生行间距，新增项目署名排列在分享人下方。
- 横版页脚以歌词区域下边缘定位，移除固定最小高度。短歌词优先居中，但必要时向下移动，给封面、歌曲信息及实际页脚留足空间，避免重叠。
- 竖版区域估算按可见行计算；真实页脚保持自然高度，不参与 flex 压缩，长文字继续换行。
- 页脚固定使用内置 Smiley Sans（得意黑）v2.0.1，独立于歌词字体；未增加第三个可选字体预设。未修改上游字体字节，随桌面和 Pages 分发原许可证，字体与许可证 SHA-256 由分发测试校验。
- 已纳入 Dependabot PR #181、#182 的更新。具体提交和后续维护流程见 [Dependabot 文档](../dependabot.md)。CI 对过期 Web Lite 仍报错，并提供重建文件供检查。

## 本地证据

环境：Windows，Node.js 24.14.1，Playwright 1.63.0；GitHub CI 的 Node.js 22 结果仍需后续 PR 验证。

- 类型检查、Lint、核心测试、稳定性测试、字体许可证与 Pages 分发、Web Lite 构建一致性检查通过。
- 生产依赖审计通过，critical/high/moderate/low 均为 0。初次审计响应不完整，重试成功；原始结果保存在 `output/v6.3.5-production-audit.json`。
- Chromium 完整回归首次为 31 通过、1 失败、1 个按配置跳过的性能基准。唯一失败为韩文宽度旧基线 920；使用未修改的 v6.3.4 `index.html` 在相同新版浏览器中也得到 940，更新 Windows 基线后该项单独复测通过。
- 新增预览与 ExportCardHost 的真实字体加载、底部对齐和不重叠断言，通过针对性浏览器复测。
- Firefox、WebKit 各自完成 Pages 启动、编辑、三款内置字体加载、本地封面及 PNG 下载检查。
- 内嵌浏览器人工交互覆盖仅分享人、仅项目名称、双行、全部隐藏与长署名换行。预览和导出宿主页脚底边误差均小于 0.01 CSS 像素；全部隐藏时不存在页脚或附件容器。
- 生产构建和 3 项 render-boundaries 回归通过；关键模块和 Electron 运行时覆盖率检查通过。
- Electron 42.11.3 已构建为本地未安装包。下载源发生 TLS 中断后，替代下载的归档通过 GitHub 官方 SHA-256 `336993fd3fe7423b1dc8c15db6659ab6f6f07778cc3de49a295910cf56d6f37e` 验证。沙箱 preload、静态资源一致性及 `--unpacked-only` 运行清单检查通过。
- 完整 `desktop:interaction-test` 通过：单实例、启动来源、语言、剪贴板、设置、导入历史、自动保存、历史传输、AI 错误处理和更新器；更新器覆盖真实 HTTP 下载、取消、SHA-512 校验失败及安装交接夹具。
- 发布 CI 暴露导入卸载用例的时序缺陷，本地也复现：测试夹具的异步界面切换尚未提交，就放行了保存回调。用例现在先确认界面卸载和事务取消，再放行保存；保留后续请求必须为空的断言。四种卸载场景各重复 8 次，32 次全部通过。
