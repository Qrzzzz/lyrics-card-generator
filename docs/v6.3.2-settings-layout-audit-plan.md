# v6.3.2：第 3～5 步设置区布局审计与方案

日期：2026-09-13。状态：审计方案已进入实施；本地实现与验证进展见 [实现与验收](testing/settings-layout-v6.3.2.md)。下文现状证据均指审计基线。

## 1. 结论与边界

需要重整设置项的布局规则与局部结构，保留现有 React 控件、业务状态及左右工作区框架。当前并非完全没有自适应，而是三套外层网格加一套行内网格彼此独立，且部分设置未接入网格。继续逐项调宽度不能满足“同一套算法、宽时每排 2～3 项”的要求。

建议采用一个按设置区实际内容宽度计算的 1／2／3 列模型，配合统一的设置单元。步骤、窗口宽度和左右比例不再分别决定设置项的列数。设置项根据内容类型使用适当控件，但不得自行定义另一套外层列宽算法。

最初审计阶段仅新增本文档。审计基线为分支 `codex/v6.3.2`、HEAD `59e60b3`，审计时 package.json 版本为 `6.3.1`；已有未跟踪 `output/` 保留。该审计阶段没有更改产品源代码、版本号、生成文件或远程状态；后续实施已获用户授权。

“所有尺寸”按可验证的范围定义：桌面支持的最小窗口到超宽屏、允许的全部分割比例，以及 Web Lite 的窄屏降级；极小窗口允许纵向滚动和单列。不能用缩小文字、截断必要标签或隐藏设置来保证一屏容纳全部内容。

### 列宽推导示例

以下是 CSS 推导，假设 1rem=16px、默认网格间距 12px、项目数量足够；不是浏览器截图测量。

| 设置组可用宽度 | rows | toggles | pairs |
| --- | --- | --- | --- |
| 440px | 1 列 | 2 列 | 2 列 |
| 640px | 1 列 | 3 列 | 2 列 |
| 700px | 2 列 | 3 列 | 2 列 |
| 960px | 2 列 | 3 列 | 2 列 |

rows 从 1 列变 2 列的门槛约为 684px；刚跨过门槛时，每项约 336px。SettingRow 的标签与控件并排需要约 364px，于是外层刚变两列，内部就变为上下排列。约到整个网格 740px 宽时，行内才恢复并排。这种“双重跳变”是源码可确认的结构问题。

### 待实机确认的风险

- 长语言下，内容类型控件的 nowrap、280px 局部宽度限制可能导致拥挤；是否出现实际溢出仍需测量。
- 字体编辑底部按钮组自身不换行、应用按钮 min-width 为 9rem，窄屏和长文案组合需验证。
- 设置切换层 overflow-hidden 可能掩盖溢出、裁切焦点环；不能只检查页面是否出现横向滚动条。
- 浏览器工具连续两次返回 `Unable to load browser request-header policy`，本轮未取得运行中界面截图，也未进行真实拖拽及多尺寸视觉验收。

## 3. 统一排版模型

### 3.1 唯一的列数规则

定义 W 为设置内容区扣除内边距和滚动条后的实际宽度，M 为标准单元最小宽度，G 为列间距：

```text
M = 15.5rem（默认 248px，待六语言视觉验证后可统一调整）
G = 0.75rem（默认 12px）
N = clamp(floor((W + G) / (M + G)), 1, 3)
单列宽 = (W - (N - 1) × G) / N
```

默认字号下，W < 508px 为一列，508px ≤ W < 768px 为两列，W ≥ 768px 为三列。440／640／700／960px 分别得到 1／2／2／3 列。这是设计起始值，不是已通过验收的最终阈值。

优先用设置区的 CSS 容器查询实现此模型，阈值从同一组设计 token 派生。外壳已有 ResizeObserver 只负责左右分割；不再为每一类字段加入测量器，也不建立与 CSS 同时控制列数的第二套 JS 规则。宽度取稳定父容器，避免字段重排反过来改变测量宽度。

### 3.2 排列约定

- 同一步所有常规分组继承同一列数与列线，不按字段类型或步骤编号切换列宽。普通字段占一列。
- 分组标题占整行。条件组作为完整语义区紧随所属分组；内部继续继承列线。优先使用无额外水平内缩的同规格网格，避免层层边框与 padding 改变列宽。
- 同一组的末行继续使用既定列宽，按顺序从左向右排列，不把最后一项无限拉长，不使用 dense 或视觉重排序。只有确有语义需要的编辑工作区声明占整行。
- 字体搜索／列表／草稿操作属于完整工作区，允许占整行。其方案入口、分类选择和普通字段仍复用统一网格；列表不是“设置选项格”，保留阅读型列表。
- 标签固定在控件上方，当前值与标签同行；开关可作为该标题行末端的控件。取消普通设置行在“标签左右排列”和“上下排列”之间的独立宽度切换。
- 外壳保留 1024px 堆叠策略及现有分割比例范围。窄屏仍按设置区宽度套用同一算法，而不是简单规定“移动端永远一列”。
- 宽度变化只改变轨道与换行，不重建字段、不重置草稿、不改变 Tab 顺序，不给网格轨道添加弹簧动画。

不新增用户可见的“密度模式”，不使用瀑布流。优先获得稳定阅读顺序与横向对齐，而非填满每一块空白。

## 4. 设置项设计规范

| 元素 | 统一约定 |
| --- | --- |
| 字段结构 | 标题／当前值 → 控件 → 必要说明或错误。数值不再混入 description 承担提示功能 |
| 字体 | 标签与控件正文使用现有 14px 等级，说明使用 12px 等级；不以 10px 辅助标签解决拥挤 |
| 间距 | 字段内部 6～8px，字段之间 12px，语义组之间 20px，标题至内容 8～12px；作为统一 token 收敛 |
| 交互高度 | 输入、分段选项和开关点击区域以至少 44px 为目标；紧凑主要来自并排和减少重复留白 |
| 单元高度 | 内容驱动，不锁固定高度；同排控件顶端对齐。不要为了与高说明字段等高而垂直居中悬浮 |
| 边界 | 采用轻量分组分隔，不给每项套厚卡片，不用 last-child 模拟网格最后一行的边线 |
| 长文案 | 自然换行，必要标签不得省略或仅依赖 title；分段项允许增高，使用 min-width:0 防止内容撑宽 |
| 滑块 | 名称与当前值在上，滑轨占单元全宽；自动开关与所属宽／高设置就近组合，禁用原因仍可读 |
| 条件项 | 依赖与控制项保持相邻、同组；隐藏不能留下空网格节点。隐藏当前聚焦子项时恢复合理焦点 |
| 无障碍 | 保留 label／aria-label、aria-describedby、switch／radiogroup 语义、键盘操作与可见焦点；说明 ID 稳定 |
| 草稿与状态 | DOM 使用稳定字段 key；重排不得改变已应用值、未应用字体草稿、编辑类别或搜索内容 |

常规设置不强制同高；避免长说明把整组强行扩展成巨大等高卡片。短说明直接显示，扩展说明仅用于非必要帮助，不以折叠隐藏核心功能。

## 5. 第 3～5 步的具体组织

### 第 3 步：布局

按“内容与画布”“文字排版”组织，保留原业务语义。

- 内容与画布：内容类型、横／竖版、尺寸模式采用标准字段。同组后接当前模式需要的尺寸区域。
- 自定义竖版：宽度单元包含自动宽度与宽度滑块；高度单元包含自动高度与高度滑块。计算尺寸摘要放在组标题旁，不另做大卡片。保留原值范围、禁用和自动计算逻辑。
- 横版：歌词区域宽度及高度按相同单元组合自动开关和条件滑块；保留 landscapePlan 与显示尺寸语义。
- 文字排版：字号、行高、对齐、启用翻译时的翻译比例，统一一项一格。纯音乐原有隐藏／锁定关系不变。

### 第 4 步：字体与颜色

- 两个内置字体方案与自定义方案入口组成同一网格，可按 1／2／3 列排列。统一标题、简短说明、选中状态和摘要，去除预设介绍的固定占高。
- 自定义入口明确区分“应用现有方案”与“编辑草稿”的交互语义；不得在一个 button 内嵌套另一个 button。保留现有点击行为，以独立操作区域表达编辑入口。
- 打开字体编辑器时保留现有专注编辑及草稿应用／取消流程，不把搜索结果拆成大量小设置卡片。
- 字体类别选择复用同一网格；搜索框、结果列表、草稿操作区占完整工作区。底部按钮组可换行，列表继续独立滚动，低窗口下操作区必须可达。
- 文字颜色模式与条件颜色选择使用标准字段网格，保持预设白色／自定义的现有值映射。

### 第 5 步：外观

- 背景与分隔：网格开关及条件密度作为相关单元，分隔符作为标准选择单元，共用网格。
- 显示内容：封面、Explicit 标记、专辑名、多行标题、项目签名、平台标识、分享者，使用同一规则的开关单元；保留横版、纯音乐、平台来源的条件逻辑。
- 分享者开关与条件文本输入组合在同一语义单元，减少目前独占整行造成的断裂；保留原来的显示条件和存储字段。
- 保留 `showGeneratedWatermark` 等兼容字段，以及点／线分隔符、项目签名的既有渲染契约。此次不重命名持久化数据，也不改变导出内容。

## 6. 实施顺序与文件范围

1. 建立作用于第 3～5 步的设置布局组件与 token：统一 Grid、Field、Group、复合字段插槽。先限定作用域，避免共享 SettingRow 修改影响全局应用设置或导出页。
2. 迁移第 3 步及条件尺寸组，移除其 rows／pairs／行内 auto-fit 和局部宽度补丁。
3. 迁移第 4 步方案入口、颜色与字体工作区里的常规选项，再迁移第 5 步。保留现有回调、翻译 key、状态与测试标识。
4. 删除本作用域内已无用途的覆盖规则。其他页面还在使用的旧控件保持可用；不得为了“统一”牵连本次范围外的页面。
5. 通过下述视觉及行为验收后再做版本一致性与 Web Lite 生成同步；提交、推送和发布遵循后续授权。

## 7. 验收标准

### 几何与连续尺寸

- 在隔离的真实组件测试容器中扫描 W=280～1100px，每 8px 一次，并对 508px、768px 各测 ±1px；核对 1／2／3 列、顺序、重叠与字段溢出。阈值修改后同步用 token 派生这些点。
- 桌面窗口覆盖 1000×700、1024×768、1280×720、1440×900、1920×1080、2560×1440；Web Lite 补 320／375／768px 宽及低高度 568px。
- 每种桌面宽度覆盖实际允许的最小、中间、最大左右比例，并连续来回拖拽；不能假定所有窗口都能达到 2/3。
- 验证 1023↔1024px 的堆叠切换，浏览器 100%／125%／150%／200% 缩放及 Windows 125%／150% 显示缩放。按逻辑宽度重排，触及限制时单列和纵向滚动可达。
- 常规项几何无重叠、无非预期横向滚动；字段自身 scrollWidth 与 clientWidth 差允许 1px 舍入误差。另查焦点环、裁切容器和必要文案，避免 overflow-hidden 隐藏问题。

### 内容与行为

- 六语言：简中、繁中、英文、日文、法文、西班牙文；亮／暗主题，至少包括 acrylic 主题、键盘焦点与减少动态效果模式。
- 第 3 步覆盖竖／横版、方形／自定义、自动宽高各种组合、翻译开关、纯音乐锁定；第 4 步覆盖长字体名、搜索结果空／多、系统字体不可用、脏草稿应用／取消；第 5 步覆盖背景密度、两种分隔符、分享者输入及全部条件项。
- 拖拽和缩放前后字段值、字体草稿、焦点与 Tab 顺序不变；条件操作引起的合理内容变化单独检查。不得把重排实现成卸载／重新挂载表单。
- 相同输入与样式下，预览和导出结果保持一致；此次设置 UI 改动不应改变图片像素内容或自动尺寸语义。

### 视觉与工程证据

- 对每步的单／双／三列及关键条件状态保留真实截图，核对列线、控件顶端、说明密度、末行留白和操作区可达性。数学公式正确不等于美观验收通过。
- 必须比较当前基线与候选版本在相同内容、宽度和语言下的截图；两／三列时应明显减少不必要的纵向长度，短设置不再横跨大块空白。
- 现有 `scripts/test-stepper-layout.ts:328` 仅断言三类网格规则的源码存在；已读 smoke 测试包含外层分割与导出几何，但不足以证明上述内部布局质量。实施时增加真实字段几何和交互断言，并替换过时的源码字符串断言。
- 实施阶段运行 typecheck、lint、相关布局／字体／分隔符回归、Web Lite 构建检查与相关真实浏览器用例；保留桌面最小窗口及分割拖拽验收证据。没有产品实现改动的本轮不运行全量发布测试。
